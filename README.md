# API مدیریت کارها با سلام و SQLite

بک‌اند HTTP با پاسخ JSON، بدون فرانت‌اند. جدول `tasks` هنگام شروع برنامه ساخته می‌شود و داده‌ها داخل فایل SQLite باقی می‌مانند.

## اجرا

به کامپایلر Salam و کتابخانه SQLite نیاز دارید. این پروژه با Salam 0.5.4 ساخته و تست شده است.

```sh
cd /home/tikrack/salam-sqlite-api
/home/tikrack/.salam/bin/salam build main.salam -o api
./api
```

سرور روی `http://127.0.0.1:8080` اجرا می‌شود. فایل دیتابیس پیش‌فرض `tasks.db` در پوشه جاری ساخته می‌شود. تنظیم پورت و مسیر دیتابیس:

```sh
PORT=8090 DB_PATH=/tmp/my-tasks.db ./api
```

## مستندات تعاملی Swagger

بعد از اجرای `./api`، صفحه `http://127.0.0.1:8080/docs` را باز کنید. Swagger UI شامل هر ۶ عملیات، نمونه بدنه JSON، پارامتر شناسه و پاسخ‌های موفق و خطاست. برای ارسال درخواست واقعی، عملیات را باز کنید، ورودی‌ها را وارد کنید و روی **Execute** بزنید. ساخت، ویرایش و حذف از این صفحه روی دیتابیس جاری اعمال می‌شوند.

سند OpenAPI در `http://127.0.0.1:8080/openapi.json` ارائه می‌شود و برای واردکردن در ابزارهای API نیز قابل استفاده است. آدرس API از مبدأ همان صفحه گرفته می‌شود؛ تغییر `PORT` نیاز به تغییر مستندات ندارد.

Swagger UI نسخه `5.33.1` از مخزن رسمی `swagger-api/swagger-ui` در پوشه `docs/assets` قرار گرفته است؛ هنگام استفاده به CDN یا اینترنت نیاز ندارد. مجوز اصلی و مجوز وابستگی‌های باندل نیز در همان پوشه هستند. سند با ماژول `net.http.swagger` زبان سلام تولید می‌شود. برای اجرای فایل باینری از پوشه‌ای دیگر، مسیر فایل‌های مستندات را مشخص کنید:

```sh
DOCS_ASSETS=/home/tikrack/salam-sqlite-api/docs/assets /home/tikrack/salam-sqlite-api/api
```

## مسیرهای API

| متد | مسیر | کاربرد |
| --- | --- | --- |
| GET | `/health` | بررسی سلامت |
| GET | `/tasks` | فهرست کارها |
| POST | `/tasks` | ساخت کار؛ پاسخ 201 |
| GET | `/tasks/:id` | دریافت یک کار |
| PUT | `/tasks/:id` | جایگزینی عنوان و وضعیت |
| DELETE | `/tasks/:id` | حذف کار؛ پاسخ 204 |

بدنه POST و PUT:

```json
{"title":"یادگیری سلام","completed":false}
```

عنوان الزامی است، فاصله ابتدا و انتها حذف می‌شود و طول آن باید بین ۱ و ۵۰۰ بایت باشد. `completed` اختیاری است و پیش‌فرض آن `false` است؛ PUT نیز در صورت حذف این فیلد آن را `false` می‌کند. شناسه باید عدد صحیح مثبت باشد. حداکثر اندازه بدنه درخواست ۸ کیلوبایت است.

پاسخ نمونه:

```json
{"id":1,"title":"یادگیری سلام","completed":false}
```

ورودی نامعتبر پاسخ 400 و شناسه ناموجود پاسخ 404 دارد. خطاهای برنامه به شکل `{"error":"message"}` برمی‌گردند. کوئری‌های مربوط به ورودی کاربر پارامتری هستند.

```sh
curl -X POST http://127.0.0.1:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"یادگیری سلام","completed":false}'

curl http://127.0.0.1:8080/tasks

curl -X PUT http://127.0.0.1:8080/tasks/1 \
  -H 'Content-Type: application/json' \
  -d '{"title":"یادگیری سلام","completed":true}'

curl -X DELETE http://127.0.0.1:8080/tasks/1
```

## تست

بعد از ساخت فایل اجرایی:

```sh
python3 test_api.py
```

۷ تست یکپارچه شامل CRUD، ماندگاری داده بعد از راه‌اندازی مجدد، متن فارسی و کوتیشن، رشته شبیه تزریق SQL، JSON نامعتبر، نوع اشتباه فیلدها، شناسه نامعتبر و رکورد ناموجود اجرا می‌شود. تست‌ها همچنین سند OpenAPI، مثال قابل اجرا، پارامترها، پاسخ بدون بدنه 204، هدر Location و ارائه محلی فایل‌های Swagger UI را بررسی می‌کنند. تست‌ها سرور را روی پورت موقت اجرا می‌کنند، از دیتابیس موقت استفاده می‌کنند و آن را پاک می‌کنند. اسکریپت تست فقط از کتابخانه استاندارد Python استفاده می‌کند.

این نمونه احراز هویت ندارد و برای اجرای محلی تنظیم شده است.
